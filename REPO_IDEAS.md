# Repository Roadmap

A recruiter scanning a student profile mainly checks two things: *does the pinned work match the stated focus*, and *is there evidence of finished, not just started, things*. The list below is grouped by your stated interests — pick a handful to actually build rather than creating all of them as empty shells.

## ⭐ Recommended 6 to pin

Pin a spread across your fields, not six of the same kind — this shows range without diluting focus.

| # | Repo | Why pin it |
|---|------|------------|
| 1 | **omeyme-ca** (your profile repo) | Pinning your own README repo is optional but common — skip if you'd rather use the slot for a project. |
| 2 | `portfolio-website` | Your personal site — already built, ties everything together. |
| 3 | `business-process-analyzer` or similar MIAGE-flavored project | Signals the business-systems side that differentiates you from a pure CS profile. |
| 4 | A **web dev** full-stack project (see below) | Shows practical, shippable engineering. |
| 5 | An **AI/data** project (see below) | Backs up the "future AI engineer" tagline with actual work. |
| 6 | A **database design** project (see below) | MIAGE-specific strength; most CS-only profiles skip this. |

## Business Information Systems (MIAGE-specific)

- **business-process-analyzer** — a small tool that models a business process (e.g. an order-to-cash flow) as a flowchart/BPMN-style diagram from structured input.
- **erp-mini** — a simplified inventory/invoicing module (stock, clients, invoices) — classic MIAGE capstone territory.
- **merise-to-sql** — a project that takes a Merise conceptual data model (MCD) and generates the corresponding SQL schema.
- **decision-dashboard** — a Power BI or web dashboard analyzing a sample business dataset (sales, HR, or finance) with real insights, not just charts.

## Web Development

- **portfolio-website** — your personal site (already built with Next.js/React).
- **fullstack-task-manager** — a CRUD app (React/Next.js + a backend + database) — the standard but essential "I can ship a real app" proof.
- **api-starter-kit** — a clean, documented REST or GraphQL API boilerplate (Node/Express or similar) you can reuse across projects.

## AI & Data

- **student-performance-predictor** — a small ML model predicting an outcome (grades, dropout risk, etc.) from a public education dataset — directly relevant to your background.
- **data-cleaning-toolkit** — reusable Python scripts/notebooks for cleaning and exploring messy datasets — less flashy than ML, but recruiters notice fundamentals.
- **nlp-text-classifier** — a beginner-friendly but complete text classification project (spam detection, sentiment analysis) with a clear write-up.

## Databases

- **sql-query-library** — a curated set of solved SQL problems (joins, window functions, optimization) with explanations — great for demonstrating depth without a "flashy" app.
- **db-schema-portfolio** — 2–3 well-documented database schemas (ERP, e-commerce, library system) with ER diagrams — ties directly into your MIAGE coursework.

---

### A few notes on execution

- A **README per repo** matters more than the code itself for a recruiter's first pass — each one should explain *what it does*, *why you built it*, *how to run it*, and *what you'd improve*.
- Finish **3–4 projects well** before starting more — a profile with two polished, working repos reads stronger than ten half-started ones.
- Commit in small, readable steps rather than one giant upload — your commit history is part of the impression.
